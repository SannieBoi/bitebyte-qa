# BUG-003: Sign up: server accepts usernames and passwords that break the signup rules when JavaScript is off

## Preconditions

- JavaScript disabled in the browser

## Steps to reproduce

1. Open Sign up
2. Enter username `a`, a valid email, password and confirm password `abc`
3. Click Sign up
4. Check the users table (SQL check Q1)

## Test data

Username: a
Email: nojs@test.com
Password: abc

## Expected result

Server rejects the username (3–15 characters) and the weak password; no account is created.

## Actual result

Account created (`5 | a | nojs@test.com`) and the user is redirected to the login page.

## Reproducibility

Always

## Attachments

_None: result is visible in the database / page behavior described above._

## Notes

`signup.php` only checks for empty fields, email format and matching passwords. Username length and password rules exist only in `signup.js`.
